<objective>
Build CachingProvider<P> that implements alloy's Provider trait (intercepting get_logs), add FinalityConfig for finality-aware caching, add BlockHeaderCache trait for block header caching, wire into Erc20Source, and update the example.

Purpose: This is the integration layer that makes the cache transparent — Erc20Source calls provider.get_logs() and hits the cache automatically. Block headers are cached via a separate trait method. Two different reducers sharing the same filter parameters share the cache without coordination.
Output: Working end-to-end caching — second run over same range makes zero RPC calls.
</objective>

  <name>Task 1: CachingProvider, FinalityConfig, and BlockHeaderCache trait</name>
  <files>src/modules/evm_cache.rs</files>
  <behavior>
    - FinalityConfig::EthereumMainnet.depth() returns 64; Arbitrum returns 0; Custom(N) returns N
    - CachingProvider get_logs: fully cached range returns logs from cache with zero inner.get_logs calls
    - CachingProvider get_logs: partially cached range only fetches uncovered gaps from inner provider
    - CachingProvider get_logs: range within finality window delegates entirely to inner provider
    - CachingProvider get_logs: range spanning finality boundary caches the finalized portion only
    - CachingProvider get_logs: extracts filter address and topics correctly for hash computation; multi-address/multi-topic-per-slot filters bypass cache
    - BlockHeaderCache: get_or_fetch_block_header returns cached header on second call without RPC
    - Two CachingProviders with same LogCache (Arc) and same filter see each other's cached data
  </behavior>
  <action>
    Add to `src/modules/evm_cache.rs`:

    1. `pub enum FinalityConfig` with variants EthereumMainnet (64), Arbitrum (0), Custom(u64). Method `pub fn depth(&self) -> u64`.

    2. `pub struct CachingProvider<P: Provider> { inner: P, cache: Arc<LogCache>, finality: FinalityConfig }` with:
       - `pub fn new(inner: P, cache: Arc<LogCache>, finality: FinalityConfig) -> Self`
       - `pub fn cache(&self) -> &Arc<LogCache>` — accessor for external use

    3. Implement `Provider for CachingProvider<P>` where `P: Provider + Clone`:
       - `fn root(&self) -> &RootProvider<_>` — delegates to `self.inner.root()`. Note: the return type is `&RootProvider<Ethereum>` when P uses Ethereum network. This is key — check alloy Provider trait signature carefully. The trait uses an associated `Network` type. Use `<P as Provider>::Network` if needed, or rely on the generic impl where alloy handles this via `root()` returning the concrete type.
       - Override `async fn get_logs(&self, filter: &Filter) -> TransportResult<Vec<Log>>`:
         a. Extract single address from filter. If filter has zero or multiple addresses, delegate to inner.
         b. Extract topics (topic0-3). If any topic slot has multiple values, delegate to inner (cache doesn't handle OR filters per slot).
         c. Extract from_block/to_block as u64. If missing or tag-based (latest/pending), delegate to inner.
         d. Compute filter_hash via `compute_filter_hash`.
         e. Fetch current chain tip: `self.inner.get_block_number().await?`. Compute finality boundary: `chain_tip.saturating_sub(finality.depth())`.
         f. Clamp cacheable range: `safe_to = min(to_block, finality_boundary)`.
         g. For cacheable portion [from_block, safe_to]:
            - Get scanned ranges from cache (spawn_blocking).
            - Compute gaps via `compute_gaps`.
            - For each gap, build a sub-filter and call `self.inner.get_logs()`.
            - Insert fetched logs into cache (spawn_blocking).
            - Record the gap as scanned (spawn_blocking).
            - Retrieve all cached logs for [from_block, safe_to] (spawn_blocking).
         h. For unfinalised portion [safe_to+1, to_block] (if any): call `self.inner.get_logs()` with a sub-filter.
         i. Combine cached + unfinalised logs, sort by (block_number, log_index), return.

    4. `#[async_trait::async_trait] pub trait BlockHeaderCache` with:
       - `async fn get_or_fetch_block_header(&self, height: u64) -> Result<Option<(/* hash */ [u8;32], /* parent_hash */ [u8;32], /* timestamp */ u64)>, Erc20SourceError>`.
       - Default impl for any `P: Provider`: just calls get_block_by_number and extracts fields.

    5. Implement `BlockHeaderCache for CachingProvider<P>`: check LogCache first, if miss, call inner provider, cache the result, return.

    For filter parameter extraction: alloy `Filter` has methods `address`, `topics` (or direct field access). The `address` field is `FilterSet<Address>` which can be empty, single, or multiple. Topic fields are `FilterSet<B256>`. Use pattern matching to extract single values; bail to inner provider for complex cases. This is the "Pitfall 1" from RESEARCH.md — handle it carefully.

    For spawn_blocking: LogCache methods are synchronous. Wrap calls in `tokio::task::spawn_blocking` with `cache.clone()` (Arc). Use `spawn_blocking(move || { ... }).await.map_err(...)`.
