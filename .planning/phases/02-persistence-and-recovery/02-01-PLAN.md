**Step 2: Create src/storage/mod.rs with:**

Storage trait definition (sync methods per locked decision):

```rust
pub trait Storage: Send + Sync + 'static {
    type Error: std::error::Error + Send + Sync + 'static;

    // Events
    fn write_events(&self, source_id: &str, events: &[StoredEvent]) -> Result<usize, Self::Error>;
    fn events_in_range(&self, source_id: &str, from: (i64, i64), to: (i64, i64)) -> Result<Vec<StoredEvent>, Self::Error>;

    // Snapshots
    fn write_snapshot(&self, snapshot: &Snapshot) -> Result<(), Self::Error>;
    fn latest_snapshot(&self, source_id: &str) -> Result<Option<Snapshot>, Self::Error>;
    fn snapshots_before(&self, source_id: &str, cursor: (i64, i64)) -> Result<Vec<Snapshot>, Self::Error>;

    // Anchors
    fn write_anchor(&self, anchor: &Anchor) -> Result<(), Self::Error>;
    fn read_anchor(&self, source_id: &str, name: &str) -> Result<Option<Anchor>, Self::Error>;

    // Coverage
    fn add_coverage(&self, source_id: &str, from: (i64, i64), to: (i64, i64)) -> Result<(), Self::Error>;
    fn is_fully_cached(&self, source_id: &str, from: (i64, i64), to: (i64, i64)) -> Result<bool, Self::Error>;
    fn cached_tip(&self, source_id: &str) -> Result<Option<(i64, i64)>, Self::Error>;
}
```

Key design decisions:
- Cursors represented as `(i64, i64)` tuple (major, minor) in the Storage API — this is the canonical INTEGER pair from the locked decision. The coordinator maps ChainCursor types to/from this representation.
- `write_events` returns `usize` — the count of rows actually inserted (not ignored by dedup). This is critical for accurate snapshot triggering per Pitfall 4 from research.
- Event payloads are opaque `Vec<u8>` per locked decision.

**Step 1: Create src/storage/sqlite.rs — SqliteStorage:**

```rust
pub struct SqliteStorage {
    conn: rusqlite::Connection,
}
```

Constructor: `SqliteStorage::open(path: &str)` and `SqliteStorage::open_in_memory()` (for tests).
Both call `configure_connection` (WAL, synchronous=NORMAL, foreign_keys=ON, busy_timeout=5000) then `MIGRATIONS.to_latest()`.

Implement all Storage trait methods:

- `write_events`: Use a transaction with `prepare_cached` for INSERT OR IGNORE. Count actual inserts by checking `changes()` after each execute (research Pitfall 4 warns about counting batch size vs actual inserts). Return total inserted count.

- `events_in_range`: SELECT with WHERE source_id = ?1 AND (cursor_major, cursor_minor) >= (from) AND (cursor_major, cursor_minor) < (to). Use the tuple comparison pattern from research: `(cursor_major > ?2 OR (cursor_major = ?2 AND cursor_minor >= ?3)) AND (cursor_major < ?4 OR (cursor_major = ?4 AND cursor_minor < ?5))`. ORDER BY cursor_major, cursor_minor ASC.

- `write_snapshot`: Simple INSERT.

- `latest_snapshot`: SELECT ... WHERE source_id = ?1 ORDER BY cursor_major DESC, cursor_minor DESC LIMIT 1.

- `snapshots_before`: SELECT ... WHERE source_id = ?1 AND (cursor_major < ?2 OR (cursor_major = ?2 AND cursor_minor <= ?3)) ORDER BY cursor_major DESC, cursor_minor DESC.

- `write_anchor`: INSERT ... ON CONFLICT(source_id, name) DO UPDATE SET cursor_major = excluded.cursor_major, cursor_minor = excluded.cursor_minor.

- `read_anchor`: SELECT ... WHERE source_id = ?1 AND name = ?2.

- `add_coverage`: Implement the interval merge algorithm from research Pattern 7 — within a transaction, find overlapping intervals, delete them, insert the merged interval.

- `is_fully_cached`: Check if the query range [from, to) is fully contained within one of the cached intervals. SELECT any interval where range_start <= from AND range_end >= to (using tuple comparison).

- `cached_tip`: SELECT MAX(range_end_major, range_end_minor) for the source. Note: SQLite doesn't have tuple MAX — query all coverage for the source and find the max end in Rust, or use ORDER BY range_end_major DESC, range_end_minor DESC LIMIT 1.

Also add a public method `write_events_and_anchor` that writes events + updates an anchor in a single transaction (for atomic anchor updates per locked decision). This is what the coordinator will call.
