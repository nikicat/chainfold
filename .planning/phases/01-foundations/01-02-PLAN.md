Define the `StateMachine` trait (per locked decisions):
```rust
use crate::cursor::ChainCursor;
use crate::event::Event;

/// Client implements this trait. Apply must be pure: no I/O, no side effects, deterministic.
/// Infallible: if an event is irrelevant, return state unchanged.
pub trait StateMachine: Send + Sync + 'static {
    type State: Clone + Send + 'static;
    type Event: Send + 'static;
    type Cursor: ChainCursor;

    /// Pure reducer. Given current state and an event, return next state.
    fn apply(&self, state: Self::State, event: &Event<Self::Cursor, Self::Event>) -> Self::State;
}
```

Define `ReducerCore<SM: StateMachine>`:
```rust
use std::sync::Arc;
use tokio::sync::watch;

pub struct ReducerCore<SM: StateMachine> {
    sm: Arc<SM>,
    sender: watch::Sender<SM::State>,
    /// Accumulated events in cursor order. Phase 1: in-memory Vec.
    /// Phase 2 will replace with SQLite-backed storage.
    events: Vec<Event<SM::Cursor, SM::Event>>,
}
```

Implement `ReducerCore`:
- `pub fn new(sm: Arc<SM>, initial_state: SM::State) -> (Self, watch::Receiver<SM::State>)` — creates watch channel, returns core and receiver.
- `pub fn apply(&mut self, event: &Event<SM::Cursor, SM::Event>)` — calls `sm.apply(current_state, event)` and sends new state via watch channel. Uses `borrow().clone()` then `send()` pattern (one clone, per research recommendation — avoid send_modify complexity).
- `pub fn apply_and_accumulate(&mut self, event: Event<SM::Cursor, SM::Event>)` — applies the event AND stores it in the events Vec. For accumulated state use case (CORE-05).
- `pub fn subscribe(&self) -> watch::Receiver<SM::State>` — returns a new receiver for watching state changes.
- `pub fn events(&self) -> &[Event<SM::Cursor, SM::Event>]` — read access to accumulated events.
- `pub fn events_in_range(&self, from: &SM::Cursor, to: &SM::Cursor) -> impl Iterator<Item = &Event<SM::Cursor, SM::Event>>` — returns events where cursor >= from && cursor < to. Linear scan for Phase 1 (Phase 2 replaces with SQLite index).

Note: `apply` takes `&Event` (borrow) for reduced state — caller keeps ownership. `apply_and_accumulate` takes `Event` (move) for accumulated state — ReducerCore takes ownership.

Note: `events` Vec requires `SM::Event: Clone` only if we need to clone during apply. Since apply takes `&Event`, no Clone bound needed on Event. The `Event<C, E>` struct derives `Clone` but that only works when both C and E are Clone. Add `Clone` bound to `SM::Event` on `apply_and_accumulate` since the event is moved in but apply needs a borrow.

Actually, simpler: `apply_and_accumulate` takes ownership of the Event, calls `sm.apply(state, &event)` (borrow), then pushes the event into the Vec. No Clone needed on E at all.
