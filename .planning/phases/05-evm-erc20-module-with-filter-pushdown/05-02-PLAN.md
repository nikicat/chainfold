2. **Add imports** from the library module:
   ```rust

       Transfer, Balances, Erc20Machine, Erc20Codec, Erc20Source, Erc20Filter,
       Provider, ProviderBuilder, Address,
   };
   ```

3. **Keep** the CLI struct (Args), `estimate_blocks_per_day()`, and the main() function logic. These are CLI concerns.

4. **Update main()** to construct Erc20Source instead of AlloyErc20Source:
   - Parse token address: `let token: Address = args.token.parse()?;`
   - Build provider: `let provider = ProviderBuilder::new().connect_http(url);`
   - Construct source: `Erc20Source::new(provider, token_bytes, Erc20Filter::AllTransfers, args.chunk_size, from_block)` where `token_bytes` is the `[u8; 20]` from `token.0 .0` (Address inner bytes)
   - When `--account` is provided, construct a *second* Erc20Source with `Erc20Filter::Account(account_bytes)` for the account history query (or keep using AllTransfers for the full fetch and filter client-side as currently done — either approach works; use the simpler one that matches current behavior)

5. **Keep** the `estimate_blocks_per_day` function — it uses Provider directly which is now re-exported. Adjust the Provider import if needed.

6. The example should run with: `cargo run --features evm --example erc20_tracker -- --rpc-url <url>`

Note: The `Erc20Source` uses a generic `P: Provider`, and the example will have a concrete provider type from `ProviderBuilder::new().connect_http(url)`. This should work without explicit type annotation since Rust infers the type.

Handle `Erc20SourceError` vs the old `SourceErr` — the example's main returns `Box<dyn Error>` so `Erc20SourceError` can use `?` if it implements `std::error::Error` (it does, via thiserror).
