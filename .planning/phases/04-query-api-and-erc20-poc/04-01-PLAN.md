1. Create `src/store/mod.rs` with the Store trait:
   ```rust
   pub trait Store: Send + Sync {
       type State: Clone + Send + 'static;
       fn get(&self) -> Self::State;
       fn subscribe(&self) -> watch::Receiver<Self::State>;
   }
   ```
   Keep the trait minimal per user decision. get() is sync and cheap (clone from watch). subscribe() returns watch::Receiver.

2. Implement `ReducedStore<S>` in the same file:
   - Holds `watch::Receiver<S>` (for get/subscribe)
   - Holds `watch::Sender<S>` (for creating new subscribers)
   - `get()` = `self.sender.borrow().clone()`
   - `subscribe()` = `self.sender.subscribe()`
   - Constructor: `ReducedStore::new(sender: watch::Sender<S>) -> Self` — takes ownership of the sender so it can create subscribers. The sender is shared from Engine at construction time.

   Actually, the better pattern: ReducedStore wraps a `watch::Sender<S>` (the authoritative copy). Engine updates it via send_modify. Store reads it via borrow/subscribe.

   Wait — Engine already has ReducerCore which owns the watch::Sender. The cleanest approach: ReducedStore takes a `watch::Receiver<S>` but also needs to create new subscribers. `watch::Receiver` does NOT support creating new subscriptions — only `watch::Sender` does. So ReducedStore MUST hold the Sender (or an Arc around it).

   Approach: Engine shares `Arc<watch::Sender<SM::State>>` with ReducedStore. ReducedStore's get() calls sender.borrow().clone(). ReducedStore's subscribe() calls sender.subscribe(). Engine's ReducerCore is refactored so the watch::Sender is behind Arc and shared.

   Concrete design:
   - Extract the watch::Sender from ReducerCore into `Arc<watch::Sender<SM::State>>`
   - ReducerCore keeps an `Arc<watch::Sender>` instead of owned `watch::Sender`
   - ReducedStore holds `Arc<watch::Sender<SM::State>>`
   - Engine exposes a method `pub fn store(&self) -> ReducedStore<SM::State>` that clones the Arc

   Alternative (simpler): Keep ReducerCore as-is. Have Engine expose a `reduced_store()` method that returns `ReducedStore` holding a clone of the `watch::Sender` via `Arc`. But watch::Sender is not Clone. So the Arc-wrapping must happen at construction.

   Final design:
   - ReducerCore::sender becomes `Arc<watch::Sender<SM::State>>`
   - All send_modify/send_replace calls go through the Arc (Deref works)
   - ReducedStore holds `Arc<watch::Sender<SM::State>>`
   - Engine::reduced_store() returns ReducedStore cloning the Arc from core

3. Refactor Engine to use `Arc<S>` for storage:
   - Change `storage: S` to `storage: Arc<S>` in Engine struct
   - Engine::new() takes `Arc<S>` instead of `S`
   - All `self.storage.method()` calls work unchanged via Deref
   - Engine::storage() returns `&S` (deref through Arc)
   - Update recovery.rs: engine.storage() still returns &S, no change needed in recovery code
   - Update all existing tests: wrap storage in Arc::new() at construction sites

4. Implement blanket `impl<S: Storage> Storage for Arc<S>` in storage/mod.rs — this allows `Arc<InMemoryStorage>` and `Arc<SqliteStorage>` to satisfy `S: Storage` bounds directly. All methods delegate to `(**self).method()`. This is cleaner than changing Engine's generic from `S: Storage` to something else.

   Wait — actually with `storage: Arc<S>` where `S: Storage`, and all method calls go through `self.storage.write_block(...)`, Deref handles this automatically since Arc<S> derefs to S. But the type `Arc<S>` does NOT implement `Storage` unless we add a blanket impl. Since Engine's field is `storage: Arc<S>` and methods are called on `&self.storage` which auto-derefs... actually `&Arc<S>` auto-derefs to `&S`, so `self.storage.write_block(...)` calls `S::write_block(&*self.storage, ...)`. This works. The Storage trait is on S, not Arc<S>, and auto-deref handles it.

   The only issue is where S: Storage is a trait bound and someone passes `Arc<InMemoryStorage>` as S directly. In that case we need the blanket impl. Let's add it for ergonomics but Engine internally stores `Arc<S>` and uses auto-deref.

5. Update `src/lib.rs` to add `pub mod store;` and re-export `Store` and `ReducedStore`.

6. Write tests in `tests/store_tests.rs` covering all behaviors listed above.

7. Run ALL existing tests to ensure the Arc refactor doesn't break anything. The Engine tests create Engine::new(core, storage, codec, config) — change these to Engine::new(core, Arc::new(storage), codec, config).
